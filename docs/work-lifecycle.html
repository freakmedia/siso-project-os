Work lifecycle

A cold agent must be able to find the current outcome, ownership, exact write authority, coordination context, proof bar, return destination, landing state, and durable lessons without reconstructing chat.

Canonical chain

task → mission/resume → sprint lane → run unit/packet → work claim → attempt/return → independent verification → delivery/landing → task evidence → durable knowledge

Every arrow is an explicit ID or repository-relative pointer. No dashboard or generated page writes backward into this chain.

Task state

TransitionRequired contract
backlog → in_progressOwner, claim time, dependencies complete.
in_progress → blockedBlocker reason, start time, required unblocker.
blocked → in_progressResolution execution-log entry.
in_progress → completedAcceptance evidence and passed or waived verification.
non-terminal → cancelledActor, time, and reason.

Task creation holds the registry lock, scans every lifecycle/archive folder, writes a temporary directory, and atomically renames it. Archive is recoverable and only accepts terminal tasks.

Mission and resume

One active mission lock names objective, owner ancestry, tasks, sprint, run, and heartbeat. Stale ownership is quarantined explicitly. Resume snapshots are immutable JSON; .agents/briefs/CURRENT.html is only an atomic pointer projection with embedded JSON.

Sprint lanes

A sprint groups existing tasks and required gates. Each lane has an immutable brief packet, state JSON, append-only log, returns, explicit dependencies, and a concrete write fence. Overlapping fences require dependency sequencing. Sprint completion requires passing lanes and satisfied required gates.

Runs and packets

A run freezes an execution attempt over one or more tasks. Units declare dependencies and write fences. Packets name anchors, facts, decisions, constraints, actions, checks, return fields, and stop conditions. Dispatch pins packet digests in the run queue. Changed instructions create an immutable amendment.

Returns are worker evidence, not verdicts. Attempts store attempt receipts, verification receipts, and one terminal result. The run ledger is ordered JSONL. Closeout refuses live claims, missing packet digests, non-terminal units, missing result records, unresolved gates, or unclassified output.

Claims and verification

A work claim reserves repository-relative paths for one task/run/unit/attempt at a base SHA. Conflicting active reservations fail. Release requires either passed independent verification or a durable blocked result. Verification recomputes the write-fence verdict from changed files and rejects self-verification.

Delivery and landing

A delivery plan fixes tasks, run, allowed destination, candidate policy, required gates, and push policy. A landing receipt links the same run/unit/candidate to its independent verifier and gate receipts. When push is authorized, landed state requires post_sha === remote_sha and passed remote equality.
