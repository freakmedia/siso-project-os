# Durable project memory

Store one durable, cross-run fact per Markdown file. A memory is not a task, status report,
transcript, or raw research dump.

Each file has schema-backed frontmatter and a short body explaining:

1. the fact or lesson;
2. why it matters;
3. how future work should apply it;
4. the evidence and dependency paths that make it falsifiable.

Use an active, superseded, or retracted status. Never erase a contradicted memory; point it to
the replacement or record the retraction reason. `INDEX.md` is generated from frontmatter and is
not an alternate writer.
